# 当前版本与验证

更新时间：2026-07-22。

## 发布配置

当前发布基线标记为 `.cw1`，核心设置如下：

| 项目 | 值 |
| --- | ---: |
| 模型 profile | `qwen-layer` |
| hidden / intermediate | 2048 / 11008 |
| Q heads / KV heads / head dim | 16 / 2 / 128 |
| 计算核 | 2 × 8×64 |
| 峰值 | 1024 MAC/cycle（两 CU） |
| weight tile FIFO | 2 |
| weight load II | 2 |
| cross-wave DATAFLOW | 1 |
| wave result FIFO | 33 |

## 功能验证

| 范围 | 负载 | 结果 |
| --- | --- | --- |
| 闭环 CSim | resident decoder layer | PASS |
| 闭环 C/RTL CoSim | 有限深度 stream，死锁检测开启 | PASS |
| 随机权重 hw_emu | 标准尺寸 decoder layer、position 0 | PASS，2048 个输出 `max_raw_error=0` |
| Attention prefill | 8-token 分阶段旧基线 | 关键路径 PASS；尚未用 `.cw1` 完整重跑 |
| U50 hardware | 200/300 MHz xclbin | 暂缓；测试机 SC firmware not ready |

CoSim 在当前跨 wave 重叠版本测得 6129 cycles，立即执行基线为 6265 cycles，降低 2.17%。该小型闭环用于验证 FIFO、握手和重叠行为，不代表标准尺寸 layer 延迟。

## 标准尺寸 hw_emu 性能

完整随机权重 decoder layer 的 `.cw1` 活跃区间为 2,278.671 µs。以 hw_emu 的 300 MHz 时钟模型换算：

| 指标 | `.cw1` | 未重叠基线 | 变化 |
| --- | ---: | ---: | ---: |
| 周期/layer | 683,601 | 714,495 | -30,894（-4.32%） |
| 200 MHz 等效延迟 | 3.418 ms | 3.572 ms | -4.32% |
| 200 MHz 等效吞吐 | 22.55 GMAC/s | 21.57 GMAC/s | +4.54% |

“等效”表示用仿真周期除以目标频率，并非真实板卡实测。

### 代表性子负载

| 子负载 | 形状/说明 | 周期或效率 |
| --- | --- | ---: |
| O projection | K=N=2048，16 waves | 46,898 cycles，69.87% shape efficiency |
| O projection 稳态 wave | ideal 2048 cycles | 后续 wave 平均 2210.4 cycles |
| Attention prefill tile | position 0..63，1 tile | 约 38,097 cycles，PASS |
| Attention decode | context 65 / 96，2 tiles | 约 74k cycles，PASS |

标准 layer 按有效 token/shape 归一化后的利用率约 88.09%；按两个 8×64 CU 的全部物理 lane 计算约 11.01%。差异主要来自单 token decode 只填充 8 行中的 1 行，不应被解释成 weight load 与 compute 完全没有重叠。

旧版 8-token prefill 分阶段估计为 6,379,917 cycles/layer、29.0 GMAC/s、9.44% 双 CU 物理利用率。它早于 `.cw1`，只用于说明 prefill 的工作量和仿真规模，待新版本按阶段重跑后再替换。

## HLS 结果

当前完整 controller HLS 估计：

| 项目 | 结果 |
| --- | ---: |
| estimated clock | 3.746 ns（266.93 MHz） |
| BRAM_18K | 488 |
| DSP | 90 |
| FF | 421,880 |
| LUT | 390,283 |

投影数据流局部估计约 3.182 ns。当前主要时序/II 风险不在块级 kernel 接口，而在 `accumulate_cc8_flash_pv_one_core`，其 II 为 4；该路径包含在线 Softmax 后的 PV 累加、归约和状态更新。

## 下一步

1. 用 `.cw1` 分阶段重跑标准 prefill，更新旧基线。
2. 优化 FlashAttention PV 累加的依赖链和 bank/归约结构，保持数值误差约束。
3. 实现 Split-M 或多请求并行，提高单 token decode 的物理 lane 利用率。
4. 在 SC 正常的 U50 上重新验证 200 MHz 镜像，再逐步提高频率。
5. 用真实 3B 权重验证跨 HBM bank 的完整容量映射和多 layer 稳定性。
